# CR-0002 — Working integrity triggers and a single protocol roster

> **Status:** RATIFIED_CANONICAL

## 1. Change Proposal

Two defects were provable by execution rather than by reading.

**Integrity triggers did not run.** `docs/03_storage_and_database/INTEGRITY_TRIGGERS.md`
referenced a table `evaluations` and a column `NEW.seq`. The schema has
`evaluation_attempts` and `sequence_no`. Loading those triggers over the canonical
DDL made every `INSERT INTO artifact_refs` fail:

```
INSERT INTO artifact_refs (owner_type='PROJECT') -> no such table: main.evaluations
```

Its whitelist also admitted only 4 owner types while the `CHECK` constraint admits
16, so 12 legal owner types would have been aborted and `EVALUATION`, which the
trigger accepted, is not a legal value at all. A second, incompatible draft lived in
`docs/03_DATABASE_AND_STORAGE.md`. Neither was normative: section 13.2 contained no
trigger definition, while `REQ-S13-003` requires generated integrity triggers whose
conformance tests cover every owner type.

**The protocol roster existed twice.** Section 7.2 lists 19 protocols.
`spec/version_manifest.yaml`, `spec/authority.yaml` and `spec/maturity.yaml` all
declared 22, and LINT-14 counted classes out of
`docs/07_schemas_and_protocols/TYPED_PROTOCOLS_22.md` — a rank 4 document. That
22-entry list is the 19 **minus `AuditLog`** and **plus** `QuantumSearchAdapter`,
`PolyglotBridge`, `EcosystemManager` and `SwarmCoordinator`. Section 3.1 excludes all
four from Core v1 and section 26 confirms they are not a dependency of M11. Anyone
starting M4 from the declared count would have built four research adapters and
omitted the one protocol that `audit_chain_verification` needs.

## 3. Authority Check

Both corrections move a definition from rank 4 to rank 1 or 2, which is the
direction `spec/authority.yaml` requires. No rank is reordered.

## 4. Security / Safety Review

The trigger change strengthens integrity: dangling polymorphic owners are now
rejected for all 16 owner types instead of 4, and the audit sequence is gapless per
scope. Restoring `AuditLog` restores the protocol that the audit chain gate depends
on. No sandbox or crypto rule is touched.

## 5. Traceability Impact

No requirement is added or withdrawn. `REQ-S13-003` moves from PENDING to
AUTOMATED_TEST, covered by `tests/conformance/test_db_integrity_triggers.py`.
