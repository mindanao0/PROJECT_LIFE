# CR-0011 — Resolve the 26 type names and build the protocol package (M4)

> **Status:** RATIFIED_CANONICAL
> **Date:** 2026-08-20
> **Workflow:** Section 27 Governed Specification Change
> **Depends on:** [CR-0002](CR-0002-integrity-triggers-and-protocol-roster.md), [CR-0004](CR-0004-canonical-bytes-and-reproducibility.md)

---

## 1. Change Proposal

Sections 7.2 and 6.2 name 26 types between them. Three resolved to a schema title. The
rest resolved to nothing — and several were near-misses for an existing title:
`OracleVerdict` beside `OracleResult`, `CheckpointRef` beside `CheckpointManifest`,
`PopulationSnapshot` beside `PopulationManifest`. Nothing said whether those were one
thing under two names or two different things.

The only file in the repository carrying real Python signatures,
`docs/07_schemas_and_protocols/TYPED_PROTOCOLS.md`, returned `dict` from every method
— which contradicts `REQ-S06-002` and makes the word "Typed" in the M4 gate false on
the first line. Anyone starting M4 would have copied it, or invented 20 signatures and
rewritten them once someone decided what the near-misses meant.

## 2. Decision

`spec/protocol_types.yaml` resolves every name into exactly one of three kinds.

**ALIAS (11)** — a second spelling of an existing schema title. The schema is
canonical and the signature uses its name, so `PopulationSnapshot` becomes
`PopulationManifest`, `OracleVerdict` becomes `OracleResult`, `CheckpointRef` becomes
`CheckpointManifest`. The contract-era spellings remain importable so a reader
following section 7.2 lands on the right type.

**IN_PROCESS (15)** — a value that never crosses a process boundary, so it gets a
dataclass and deliberately no schema: a schema would imply a wire form that does not
exist. Where the value is persisted the table is named, so
`SandboxExecutionResult` says `evaluation_attempts` and `AuditReceipt` says
`audit_events`.

Two of these needed care. `CapabilityVerdict` is **not** schema 10 — that is
`CapabilityContract`, the declaration being checked, while this is the outcome of
checking it. `PolicyVerdict` is **not** schema 18 — that is `PolicySnapshot`, the
policy itself. Treating either pair as one type would have merged an input with an
output.

**NEW_SCHEMA (6)** — `ValidationReport`, `PreflightReport`, `GenerationSummary`,
`RunStatus`, `EvolutionReport`, `ExportManifest`. Each is returned by an SDK call
reachable through `evolve <cmd> --json`, so each crosses a boundary and needs a
schema. They are recorded and **not** created here; see the open question.

## 3. The package

`src/evolution_engine/` now holds the typed boundary:

- `types.py` — the identifiers with their two derivation kinds, three state enums
  mirroring `spec/fsm_states_57.yaml`, and a dataclass per IN_PROCESS type.
- `protocols/` — the 19 Core v1 protocols across 15 modules, generated by
  `tools/generate_protocols.py` from section 7.2 with every type name resolved through
  `spec/protocol_types.yaml`, so a signature cannot name something that does not exist.

Bodies are `...`. The M4 gate is "19 Typed Python Protocols with zero type errors",
not working code; behaviour lands at M5 and later behind these same signatures, which
is what `REQ-S29-005` requires.

**`mypy --strict` reports no issues across 18 source files.** That is the first time
anything in this repository has been checked against a compiler rather than against
another document.

## 4. Maturity

Computed maturity moves **M3_SCHEMAS → M4_PROTOCOLS**, earned rather than declared:
`m4_protocols()` requires the 19 named classes to be real `typing.Protocol`
subclasses, every method fully annotated, `mypy --strict` clean, and
`requirements.lock` present. CR-0010 proved that predicate rejects empty files.

`mypy` is added to the lock, since the gate now depends on it.

## 5. Open question — the six wire types

`REQ-S15-001` pins the registry at exactly 26 schemas and `REQ-S15-006` forbids a 27th
being counted. Adding six is a governed change with wide reach: both those
requirements, the CI job literally named `schema_registry_exact_26`,
`version_manifest.schemas_count`, LINT-14, `EXPECTED_FILES` in
`tools/validate_schemas.py`, the manifest, and a fixture pair each.

It does not block M4 — no protocol in section 7.2 returns one of them — so it is
recorded rather than rushed. The choice is between raising the registry to 32, or
declaring one CLI envelope schema with a discriminated union over the six.
